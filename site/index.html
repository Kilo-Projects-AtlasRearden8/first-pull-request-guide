Welcome to Your First Pull Request

GitHub is a place where people store, share, and improve projects together. You do not need to be a programmer to take part. If you can click buttons and type sentences, you can contribute.

This manual walks you through the five things almost every beginner wants to do:

  1. Forking — make your own copy of a project
  2. Cloning — download that copy to your computer
  3. Branches — work on changes without touching the main project
  4. Issues — report a problem or suggest an idea
  5. Your first pull request — ask the project owner to use your changes

There is also a printable contribution checklist at the end to keep by your desk.

Each section is written in plain English, step by step. Take it one click at a time. You cannot break anything by following these instructions.

The friendliest way to read this

  • Open this guide in one window.
  • Open GitHub (github.com) in another window.
  • Do one step, then look at your screen to confirm it happened before moving on.

If a button name or menu looks slightly different on your screen, look for words that mean the same thing. GitHub changes its design now and then, but the ideas stay the same.

What you will need

  • A free GitHub account (sign up at github.com)
  • A web browser
  • About 20 minutes

That is it. You do not need to install anything for the first few sections.

Words you will meet

| Word | Plain-English meaning | |------|-----------------------| | Repository | A project's home on GitHub. "Repo" for short. | | Fork | Your own copy of someone else's repo. | | Clone | A download of a repo to your computer. | | Branch | A separate work area for your changes. | | Issue | A note about a bug or an idea. | | Pull request | A request to add your changes to a project. | | Commit | Saving a set of changes with a message. | | Main | The primary branch of a project (sometimes called master). |
