2. Forking

Forking means making your own copy of someone else's GitHub project. The copy lives under your account. You can change it however you like without affecting the original.

Think of it like photocopying a library book so you can write notes in the margins. The library's book stays untouched, and your copy is yours to mark up as much as you want.

Before you start

Find a public project you want to practice with. A good starter is any repo with a friendly "good first issue" label. You can also fork this very guide if it is hosted on GitHub.

You only need the project's GitHub page open in your browser.

Step-by-step: fork a repository

  1. Open the project's page on GitHub. It looks like github.com/username/project-name.
  2. Near the top right of the page, find the Fork button.
  3. Click Fork.
  4. GitHub asks where to put the fork. Choose your own account.
  5. Wait a few seconds. GitHub copies the project.
  6. You are now on your copy. The page title shows your-username / project-name.

That is it. You now own a copy of the project.

What just happened?

  • GitHub copied all the files and the history of the original project into

your account.

  • Your copy is independent. Changes you make do not show up in the original,

and changes in the original do not show up in your copy unless you ask for them.

  • The original project still shows the original owner as its author.

Common questions

"Will forking cost anything?" No. Forking public repositories is free.

"Do I need permission to fork?" No. Anyone can fork a public repository.

"Can I fork more than once?" You can fork a project once per account. If you want a fresh copy later, you can delete your fork and fork again.

"Will the original project owner know I forked it?" They might see a fork count go up, but they will not get a personal alert. Forking is completely normal and expected on GitHub.
