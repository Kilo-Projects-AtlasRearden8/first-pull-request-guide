# 5. Issues

An **issue** is a note on a project's page where people discuss bugs,
questions, or ideas. You do not need to change any code to open an issue.
Anyone can do it.

Think of it like a suggestion box or a repair ticket for a project. It is a
friendly way to start a conversation.

---

## When to open an issue

- You found a mistake (a typo, a broken link, wrong information).
- You have an idea for something the project should add.
- You are confused about how something works and want to ask.
- You want to volunteer to fix something.

---

## Step-by-step: open an issue

1. Go to the project's page on GitHub.
2. Click the **Issues** tab at the top of the page.
3. Click the green **New issue** button.
4. Give the issue a clear title, for example:
   - "Typo in welcome sentence"
   - "Link to chapter 3 goes to the wrong page"
   - "Idea: add a printable checklist"
5. In the big text box, write what you found or what you suggest. Include:
   - What you expected
   - What you saw instead
   - Where to find it (page name, file name, or link)
6. Optional: add labels if the project offers them (for example, `typo` or
   `idea`).
7. Click **Submit new issue**.

Your issue is now public on the project. Anyone can comment on it.

---

## What just happened?

- GitHub created a numbered conversation page for your issue.
- People working on the project can see it, discuss it, and decide what to do.
- You will get notifications when someone replies (unless you turn them off).

---

## Being a good issue writer

- Be specific. "It is broken" is hard to fix. "The link on page 2 goes to a
  404 page" is easy.
- Be kind. The people maintaining the project are often volunteers.
- One issue per topic. If you found three typos, you can put them in one issue
  or open three small ones — whichever feels clearer.
